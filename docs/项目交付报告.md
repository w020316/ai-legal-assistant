## 一、项目概述

linzAI 法律助手是一款面向普通用户与法律从业者的智能法律咨询平台，提供 AI 智能问答、案例检索、法律文书模板生成、合同文档风险分析、个人知识库管理等核心功能。

### 技术架构

| 层级 | 技术栈 |
|------|--------|
| 前端 | Vue 3 + TypeScript + Pinia + Element Plus + Vite |
| 后端 | Spring Boot 3.4 + Spring AI 1.0.0 GA + MyBatis-Plus |
| 数据库 | PostgreSQL + pgvector（向量检索） |
| 缓存 | Redis（JWT 黑名单 / 会话缓存） |
| AI | OpenAI V1 兼容 API（AgnesClient） |
| 部署 | Fly.io（前端 + 后端 + PostgreSQL + Redis） |

### 访问地址

| 后端 API | http://lawai-backend.fly.dev/api/v1/health |

### 7.9 v1.16.0 AI 回复排版根治 + 消息卡片现代重构（2026-09-09）

#### 背景

产品经理根据真机/桌面截图反馈：AI 生成内容出现 `——#大前提` 等 Markdown 标记与正文粘连、长文本成"文字墙"、字号偏小、等待首字期间无反馈；要求"页面固定、生成内容自适应"，并参照主流 AI 聊天站（ChatGPT/Claude 式）重构聊天体验。

#### 根因分析

| 现象 | 根因 |
|------|------|
| `——#大前提` 等 **Markdown 标记裸露** | 模型行首带装饰符（`——`/`·`/`,`），`markdown-it` 只在**行首**识别标题，装饰符阻挡后 `#` 变字面量显示 |
| 长文本 **"文字墙"无分段** | `markdown-it` 的 `breaks:false` 下，模型用**单个换行**（非空行）分段时会被合并为一个 `<p>`，视觉上密集无呼吸 |
| 字号/行高偏小 | 正文 14px/1.7，移动端阅读吃力 |
| 等待首字无反馈 | 仅三点加载，用户误以为卡死 |
| 旧式公文卡片 | AI 卡片带"公报左竖线 + 直角"样式，与现代 AI 对话气质不符 |

#### 本轮变更

| 方案 | 说明 |
|------|------|
| Markdown 规范化增强（`markdown.ts`） | 剥离行首装饰符（`——#大前提`→`# 大前提`）；为 `#`/`-`/`1.` 后补空格；跳过代码块保护代码 |
| 软换行正确分段 | `markdown-it` 开启 `breaks:true`：模型用单个换行也能分段，根治"文字墙" |
| 排版可读性提升（`MarkdownRenderer.vue`） | 正文 15px/1.85 行高、段落 10px 间距、标题层级加大（h2 下加细分线）、引用块高亮；移动端正文升至 16px/1.95，页面固定、内容自适应 |
| AI 卡片现代重构（`MessageItem.vue`） | 去除"公报左竖线"，改**圆角液态玻璃卡片**（细金边 + 顶部内高光）；用户气泡改右侧渐变酒红圆角；折叠区/操作栏同步现代化 |
| 等待首字反馈 | 三点脉冲旁新增"正在思考中…"文案，缓解无反馈焦虑 |

#### 构建/部署

- 前端：生产构建通过（10s），无类型/语法错误
- 部署：Git 自动部署，推送 `master` 即触发 Cloudflare Pages 更新

#### B.AI 境外慢 / "报错不断" 根因定位与修复（实测）

对 B.AI 实测定位到两个真正根因，均已修复：
1. **端点不可用**：`chat.b.ai/v1` 对 `/chat/completions` 的 POST 直接拒绝（0.6s 失败）；可用网关为 `api.b.ai/v1`（实测 OK，`/v1/models` 亦返回完整模型列表）。
2. **默认模型是「推理空模型」**：`glm-5.3-flash` 为推理模型，实测返回 `message.content` **恒为空**、正文全在 `reasoning_content`，且 `finish_reason=length`（思考耗尽 max_tokens）——导致后端收到空结果 → `AI_SERVICE_ERROR` → 频繁降级/报错；前端流式取 `delta.content` 一直取不到字 → 用户感知"思考太久、无输出"。

**修复（后端）**：
- `base-url` 默认 → `https://api.b.ai/v1`（可用网关）
- 默认模型 → `qwen3.8-flash`（实测：直接出正文、约 5s/短回复、`finish=stop` 正常）
- 超时降级按实测设定：整体 25s（覆盖完整法律答复 15~25s），流式无数据 12s 即降级 GLM→Agnes

**前端排版再放松**：行高 1.85→2.0、段落 10→14px、列表项 6→10px、标题 20→26px 上边距、正文阅读宽度 800→720px，换行更清晰。

**部署后待核对**：若 Render 环境变量已显式设置 `BAI_MODEL=glm-5.3-flash` 或 `BAI_BASE_URL=chat.b.ai/v1` 会**覆盖**默认值，需改为 `qwen3.8-flash` / `https://api.b.ai/v1` 后重部署，即可根治"慢/空/报错"。
