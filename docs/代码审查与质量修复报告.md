### 5.2.2 新发现（P1，线上，非本轮引入）：令牌吊销在生产环境整体失效

以**直接后端** URL 复测确认：

- `POST /auth/refresh` 用**同一 refresh token 连续调用两次均返回新 token**（若 Redis 正常，第二次应"已失效"）。
- 登出后 access token 仍可访问受保护接口（应被黑名单拦截）。

两处均为 **Redis(Upstash) 在生产不可达**所致：`AuthService.blacklist`（写）与 `JwtAuthenticationFilter.isBlacklisted`（读）在 v1.16 起均为 **fail-open**，Redis 一断即写不进、也查不到，令牌吊销整体失效。**此为既有问题，与 v1.17 改动无关**，但它使 F10 修复在有 Redis 时才算数——F10 逻辑正确（本地测试通过），需先恢复 Redis 连通才能线上验证。

> 待办：排查 Render 后端 `REDIS_HOST/REDIS_PASSWORD`（Upstash）连通性；恢复后按下述复测。若不修复 Redis，则"登出吊销"在生产名存实亡，建议评估是否对 `refresh` 校验改为 fail-closed。
